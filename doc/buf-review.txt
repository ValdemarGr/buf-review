*buf-review.txt* *buf-review*  Local-first pull-request review

Requires Neovim 0.10+, matching `pr` executable, Git, and authenticated `gh`.
Install this repository as a Neovim plugin (or add its root to 'runtimepath').
No setup call or Lua dependency is required. Run `:helptags {plugin}/doc` when
installing manually. Optional executable override: >lua
    vim.g.buf_review_executable = '/absolute/path/to/pr'
<
                                                        *:Review*
:Review                         Bound review: its session home. Source buffer:
                                resolve current branch's open PRs.
:Review prs [assignee=LOGIN] [state=open|closed|merged|all]
                                Choose another PR. @me/all are valid assignees.
:Review pr BASE                 Review current branch against BASE; select an
                                existing PR or save a local creation intent.
:Review sessions                Browse saved sessions, grouped by PR.
:Review sessions new            New session for current/selected PR.
:Review pull                    Fetch/reconcile bound session and prepare Git;
                                or reread current browser. Waits for completion.
:Review checkout                Explicitly switch local checkout to bound PR.
:Review start                   Legacy activity command; new inline drafts join review.
:Review leave                   Legacy activity command; membership stays unchanged.
:Review conclude                Outcome picker and Markdown conclusion composer.
:Review publish                 Send saved queue; no conclusion means draft review.
:Review move                    Move selected unsent comments into review.

Review buffers target their own repository/PR/session. From source, :Review
uses the current branch: exactly one open PR routes to it; zero or multiple
matches open the remote PR picker. Picking a PR creates a session when none
are unfinished, resumes its only unfinished session, or opens that PR's saved
sessions when several are unfinished. Rust owns these routing decisions.

:Review sessions shows every saved session grouped by PR, current PR first.
The same browser is filtered to one PR when selection is ambiguous. Enter
resumes a session; :Review pull rereads saved session state. Rows show
publication status, pending comments/changes, published counts and conflicts.
:Review sessions new creates a distinct session for the PR under the browser
cursor, selected remote PR, or bound session's PR. Existing :Review start only
controls that session's WIP; it does not create another session.

A session is a batch with a stable identity across refresh and publication.
Several sessions may belong to the same PR. Selection and saved work persist
in .review/state.sqlite3 at the repository root, scoped to the authenticated
reviewer. Switching sessions never retargets existing buffers or composers.
Cached sessions open from saved state, including after restarting Neovim.
Opening or navigating them does not automatically refresh remote state.
A PR without cached data needs its initial fetch; a PR fetched during routing
is not immediately fetched again. Selection waits for Git preparation.
:Review pull explicitly fetches remote changes, reconciles local intent and
prepares Git objects. It shows progress and waits for completion while Neovim
stays responsive. There is no :Review refresh alias.
Failed fetches retain cached work with a visible error and saved drafts.
Review comparisons follow checked-out Git HEAD. Fetch never pulls or switches
branches; reopen a diff after changing the checkout.

                                                        *buf-review-local-pr*
:Review pr master reads GitHub for the current source branch -> master, matching
both repositories and branch names. An existing open PR is used immediately;
otherwise a local PR object is created before its review session. Ordinary
create/resume/choose session rules apply. Plain :Review entry stays unchanged.
Committed comparisons use checked-out HEAD. Dirty files open their editable
local version on the right; comments require committed code and a reopened diff.
BASE must name an available local branch; fetch/create it first when absent.
Pull fetches remotes and reads checked-out HEAD without changing branches.
It does not run git pull or merge branches.

Enter on a local PR's title opens Markdown: first line title, remaining text
body. :w / :wq save locally. Sessions share the logical PR object; stale metadata
writes are rejected while composer text remains. Remote PR descriptions are
never overwritten by this composer. Local intents have no checkout action.

Publish reuses a matching open PR or creates a draft, then publishes the selected
standalone/review changes under their normal rules. Push reviewed commits with
ordinary Git/Fugitive first; Publish does not push. Creation requires a title.
PR-only Publish works without comments. Stable PR/session/comment IDs and anchors
survive binding. Failed comments do not discard a created PR. Unknown creation
results reconcile before retry; conflicting logical identities block binding
while preserving both objects and their sessions/drafts.

Selecting a PR prepares checked-out HEAD, its review base, latest fetched PR head and
original comment commits before showing review objects. Rust batch-checks local
objects and fetches only missing hashes, together. Explicit pulls wait for
preparation of newly discovered hashes.
Missing historical commits report warnings and use recorded-hunk fallback;
missing current comparison commits report an error. Preparation never checks out files.

:Review opens in the current window and tab. It never creates or jumps to a
dedicated Review tab. Each repository has one active view; another tab takes
over when :Review is invoked there. PR/session switches and o share the active
tab; unrelated user splits and unsaved native buffers are preserved. Closing
the tab does not create a replacement.
The active review view contains home or committed code panes, with
one reusable discussion split below them. A dirty right pane uses the ordinary
editable source buffer. Press o in a review diff to open its right pane as Local,
even when clean. This explicit editable mode lasts until the diff is reopened.
Commit local edits and reopen before creating comments. Unpushed commits may be
reviewed locally; publication still requires the current remote PR head.
Normal editing/search/Telescope opens ordinary source files separately.
Browsing never changes the local checkout.

                                                        *buf-review-checkout*
Home's Checkout row shows local branch, relationship to fetched PR head and
staged/modified/untracked file counts. Enter on that row or :Review checkout
switches to the PR branch. No extra keybinding or automatic checkout.

Save/discard unsaved source buffers first, including hidden buffers. Conflicts
and unfinished Git operations block switching. A clean checkout switches
immediately. With disk changes, choose Cancel (default), Stash & switch, or
Carry changes & switch. Carry uses Git's normal checks; no forced reset/rebase.
Local commits ahead of the PR are preserved. Unmodified source buffers reload;
session identities and draft anchors stay unchanged. Reopen to read the new HEAD.

Stash includes staged/unstaged/untracked changes, excluding ignored files and
reserved .review/ state. Its ordinary Git stash is named with source branch and
PR URL. A failed switch retains and reports it. Restore using Git/Fugitive,
for example :Git stash list followed by :Git stash apply --index stash@{0}.
The plugin keeps no stash registry or return lifecycle. Lua owns checkout;
Rust/SQLite retain remote PR metadata and review state only.

                                                        *buf-review-home*
Home sections: Unpulled commits (when present), Todo, Unpublished changes,
Unviewed files, Viewed files, Done,
Publication history. The header identifies the session and shows publication
status, pending and published counts. Enter on a publication opens its saved
plan, confirmed operations, provider responses and errors read-only below home.
Headings, paths and statuses use theme highlight groups. Comments show location
and author above a short preview; both lines select the same comment. Native
folds use za/zc/zo without visible fold markers. Todo uses the backend's stable
path/location/conversation ordering. Unpublished changes show destination,
conflicts, pending deletion and rejected anchors. File viewed state and comment
completion are independent.
When checked-out HEAD differs from the latest fetched PR head, the header shows
"not at remote head". Unpulled commits lists remote commits absent from HEAD,
newest first, with short commit IDs and subjects.

File rows show M +12 -3  path: modified, added (A) or deleted (D), with added
and removed line counts. Renames, copies and type changes use M. Status/counts
use theme colors. Stats belong to the checked-out comparison; missing cached counts
show ?.

Local comments retain creation-event order through publication, refresh and
restart. Replies follow their root; fetched conversations use oldest-first
provider chronology. Comment UUIDs do not define ordering.

Fetched comments/replies, including your own fetched comments, join Todo unless
you have given that individual item a thumbs-up. Only your thumbs-up matters.
Local drafts and publication receipts alone never enter the checklist.

Inline diff markers show fetched comments with [ ] none Done, [-] partly Done,
or [x] all Done. Replies count individually; only your thumbs-up matters.
Local comments are counted separately without a completion badge. Staged s/u
updates the marker immediately. Theme groups: BufReviewTodo (DiagnosticInfo),
BufReviewPartial (DiagnosticWarn), BufReviewDone (DiagnosticOk).

The active comment's exact referenced lines are highlighted on the matching
diff side while its pane is visible in the current tab. Code focus retains it;
another active comment replaces it. Replies use the root's range. Historical
views highlight verified original lines in the commented version; missing, invalid and
file-only anchors do not guess current lines. Hiding or
closing the pane clears the highlight. BufReviewCommentRange defaults to Visual.

                                                        *buf-review-mappings*
Global normal-mode defaults, using your configured <leader>:
    <leader>rs   :Review
    <leader>rr   :Review pull
    <leader>rp   :Review publish
    <leader>rcc  :Review conclude
    <leader>rcs  :Review suggest (in an eligible comment composer)

Set mapleader before loading the plugin. Existing user mappings win over these
defaults and the navigation defaults below. Bracket mappings are Review-local.

Mappings are local to Review buffers; read-only readers unless stated otherwise:
    <CR>   Open selected PR/file/comment. On diff lines, open existing threads
           as a list, including a single thread; no threads means no action.
           Enter on a list entry opens that thread. In the log, toggle the fold
           under the cursor.
    a      On a diff line or in its thread list, create a new root at that
           captured location, even when threads already exist.
           In a conversation, reply to the root, including your own thread.
    o      In a review diff, open its right pane as the editable Local file.
           Commit and reopen before commenting on changed code.
    s      Stage selected file viewed, or fetched comment Done (own thumbs-up),
           without moving.
    ]f [f  Next/previous unviewed file; no marking.
    ]r [r  Next/previous unfinished comment; no marking.
    u      Restore pending deletion, cancel new unpublished comment/reply,
           or mark file unviewed or fetched comment Todo.
    cc     Home only: conclude review.
    dd     Delete the comment under the cursor in home/thread lists/discussions.
    d{motion}, D, x
           Delete each touched comment once in those same views.

Visual a in diff creates a comment over inclusive whole touched lines.
It replaces the native a{textobject} prefix only in Review diffs. Visual <CR>
has no plugin mapping; normal <CR> continues opening existing threads.
Characterwise and linewise selections are supported; blockwise is rejected.
Visual s/u acts once per intersected file/comment in read-only lists/threads.
Visual u restores pending deletions, cancels new unpublished comments/replies,
or marks the object Todo/unviewed. Draft cancellation retains deletion's
ownership and dependency checks; selected replies are canceled before parents.
Visual d/x deletes each touched comment once, including blockwise selections.
Headings, files, dividers and spacing are ignored. Deletion requires ownership;
submitted review summaries cannot be deleted. Selecting a parent and its local
replies deletes replies first; unselected local replies block parent deletion.
Already pending deletions are ignored. Deletion stays local until publication;
deleting an unpublished draft cancels its creation. Composer and diff/source
buffers retain their normal editing keys.
Empty normal-mode motions do nothing, including d0/dh at column zero and d^
at the first nonblank character. D/d$ on an empty body line also does nothing;
visual characterwise/linewise deletion can still select that line's newline.
Within threads, Enter edits your own comment; other/unknown authors remain
read-only. Use a to reply to the root when supported, including your own thread.
PR-wide comments and summaries do not support inline thread replies.

Thread lists show styled entries without usage banners. Discussions show
themed location, author and status headers above the original Markdown body,
with dividers only between comments, never after the last comment. Dividers
and spacing are not comment objects. Both readers retain final blank spacing
without a trailing append divider. Normal a works anywhere in either reader,
including the end. It opens an ordinary Markdown composer in the same pane;
no editable footer or protected prefix.
Native a in composers and source files is unchanged.

When no comments remain, the managed thread selector or discussion closes and
focus returns to its origin. Pending-deletion comments remain visible for u
to undo the deletion and do not make the reader empty.

Actions compose with native motions, macros, :global/:vglobal and ranged :normal.
The reader remains stable while commands run. Object IDs enter one ordered
session queue; Rust executes action lists, and readers rebuild at SafeState.
Contextual u/deletion use preceding actions' results. Reads, saves and session
switches flush earlier local writes; a save finishes its own write before
returning. Pending local writes finish on editor exit. Complete a/type/save/return
sequences work in native commands. :normal! bypasses mappings as usual.
Remote publication is explicit and waits for writes and subsequent PR refresh.
Pull fetches an immutable snapshot, then queues its local merge alongside writes.
The explicit command waits for reconciliation and Git preparation.

Marking keeps cursor row/column and scroll position when entries move between
sections; positions clamp at the buffer end. Navigation uses the object under
the current cursor or identified by the focused buffer, never a remembered file,
comment or position from another pane. Home file/comment rows and thread-list
rows supply that current object. With no current object, next opens the first
eligible item and previous the last.
All next/previous motions follow the backend's stable order, start strictly
after/before the current object, and wrap to the other end. They skip excluded
items and exclude the current object at each step. Counts such as 4]f take four
eligible steps, loading only the final destination. With no other eligible item,
stay put.
The ]f/[f motions skip viewed files and ]r/[r skip Done comments, including
unpublished progress. Navigation never marks progress. Each reply counts
separately. From code with no current comment, ]r opens the first unfinished
comment at the cursor's diff line and [r the last, falling back to global Todo navigation when
that location has none. Thread-list rows identify the current comment, so next
opens the following eligible comment. Use ]f, inspect the file, press s to stage
it viewed, then ]f again. Likewise, ]r opens a comment, s stages it Done, and ]r
continues. Staging stays in the current context and bound session; it does not
navigate. Historical code cannot stage a current file viewed.
Both current-comparison diff winbars show [viewed] or [unviewed] beside the file
path. Local s/u staging updates both panes without publication.
Local file progress records its comparison commit. Commits touching that file
invalidate the local mark for another comparison, including changes later
reverted. The same filtering supplies the CLI and publication. Filtered marks
remain saved; checking out their commit and reopening restores them. Remote viewed flags
keep their existing meaning.
Unsaved composers block navigation. Navigation waits for pending local writes
before searching. Older loads never replace newer file, comment or home choices.
Opening another file closes the managed discussion anchored to a different file.
Same-file and PR-wide discussions stay; additional user-opened windows stay.
Plain s preserves cursor and scroll position. Native lowercase [c/]c diff motions
remain available.
These <Plug> mappings are available for user maps:
    <Plug>(ReviewDone)               <Plug>(ReviewTodo)
    <Plug>(ReviewViewed)             <Plug>(ReviewUnviewed)
    <Plug>(ReviewNextTodo)           <Plug>(ReviewPreviousTodo)
    <Plug>(ReviewNextComment)        <Plug>(ReviewPreviousComment)
    <Plug>(ReviewNextFile)           <Plug>(ReviewPreviousFile)

Example: >lua
    vim.keymap.set('n', '<leader>rt', '<Plug>(ReviewNextTodo)')
    vim.keymap.set('n', '<leader>rT', '<Plug>(ReviewPreviousTodo)')

                                                        *buf-review-comments*
:Review comment [review|standalone]
    Create a root at the diff cursor/range, file comment from home file row,
    or standalone PR-wide comment from home header. Explicit creation works
    even when threads already exist at the selected line.
:Review reply [review|standalone]
    Reply to selected inline thread, including your own comment.
:Review edit                    Edit selected unpublished comment.
:Review delete                  Delete selected unpublished comment.
:Review restore                 Cancel unsent deletion of a local comment.
:Review suggest                 Insert suggestion with captured immutable lines.
:Review done / todo             Stage selected fetched comment's own thumbs-up.
:Review viewed / unviewed        Stage selected file/diff progress.

New inline comments join one review per publication. Replies to unpublished
standalone parents inherit that destination. :Review move explicitly
moves the current comment, Ex range or visual selection into the review;
include unpublished parents and replies together. Sent comments cannot move.
Successfully sent comments/conclusions are immutable, including pending drafts.
Corrections use new comments or replies. PR-wide comments retain targets.

Composers contain only ordinary Markdown. Target and status appear in the
window winbar, without virtual headers in the buffer.
    :w      Save locally; keep composer open. Never publish.
    :wq     Save locally; return to originating reader/context on success.
    :q      Normal modified-buffer protection; never publish comments.
    :q!     Discard unsaved text; previous local saves remain.

This return applies to all ordinary comment composers, including explicit
edit/reply commands. A reused reader pane restores its immutable list/thread;
from home or diff, the ordinary discussion composer keeps that context visible
and closes back to it.
Closing a direct diff comment restores the originating pane and all displayed
diff panes' cursor and scroll positions from before the composer opened.

Blank new draft saves nothing. Saving an unsent comment blank cancels its
creation; nonblank saves preserve identity. Sent/fetched comments cannot be
edited or deleted. Whitespace counts as blank. Ownership/dependency checks apply.
Repeated blank writes add no events. Local event history remains append-only.
Save failures retain modified text. Switching objects/PR/comparison refuses to
replace modified composers. Refresh preserves their text. Concurrent/stale
workspace saves retry once when only unrelated state changed. A changed target
or another concurrent race fails visibly and keeps that text for reconciliation.

Suggestions are ordinary fenced Markdown `suggestion` blocks prefilled from
exact immutable line/range source. They require a root comment and available
source; replies, PR-wide or file-level comments cannot insert suggestions.

                                                        *buf-review-conclusion*
Home cc or :Review conclude selects Comment / Approve / Request changes and
opens saved summary. Draft removes an unsent conclusion without changing
history. Saving queues one optional publish_review event; repeated
unsent saves replace its projected value. Summary-only reviews are supported.
Comment and Request changes require nonblank summary; Approve may omit it.

    :w              Save outcome/summary locally.
    :wq / :x / ZZ   Save locally and return.
    :q / :quit      Stay local; saved intent remains.
    :q! / ZQ        Discard unsaved text; earlier saves remain.

Only :Review publish writes to GitHub. Missing conclusion leaves pending/draft
review comments. A queued conclusion runs after preceding saved operations.
Publication never prompts. Fetched pending roots/replies show [draft], remain
read-only and stay outside Todo/Done until submitted and fetched.

Publish follows dependencies, splitting each operation family at each dependency
depth into batches of at most eight operations. Independent comments share a
request; replies wait for newly created parents' confirmed identities.
Viewed flags and reactions are batched
by family; the conclusion follows the other operations. The authenticated
reviewer's matching pending review is reused, or created when missing.

Each confirmed operation keeps its own receipt, including successes within a
partially failed batch. Batch mutations use GraphQL aliases in one HTTP request;
the server executes fields serially, without atomicity or rollback. Each request
has a durable in-flight marker; receipts and unresolved response evidence are
saved before the next batch. An error, blocked operation or uncertain result
stops later batches. Retry keeps the
publication ID and confirmed receipts; confirmed operations never resend.
Partial comment identities/errors are retained. Resource-limited inline creates
reconcile only against their original pending review, matching reviewer, head,
exact anchor and body. Baseline comments and existing receipts are excluded;
one unique exact match recovers its receipt. An explicitly resource-rejected
missing alias retries only after a complete scoped read confirms absence.
Other unknown creates and ambiguous results remain blocked.
Unknown viewed/reaction results reconcile together with one fresh fetch before
retry decides what remains. New unrelated work waits for another publication.
Completed publications stay immutable; later work may extend or conclude the
same pending review without deleting its earlier comments or claiming them as
receipts for new local operations.

Local events receive UUIDs when created; refresh and retries preserve identity.
The publication plan coalesces intent before removing confirmed operations.
Viewed/Done toggles reversed to their known baseline stay cancelled after
refresh. A new toggle after publication is a separate local event.

Publish waits for writes, then fresh PR fetch/reconciliation. Refresh failure is
reported separately, preserving receipts. Ctrl-C interrupts waiting while
publication continues; retry stays guarded until write and refresh finish.
Before any publication writes, Git remotes are fetched and the current PR head
is checked. A different head aborts with "not at remote head". Push or update
your checkout with ordinary Git, reopen and inspect, then retry. Fetch or history errors never imply that
a local viewed mark is still valid.

                                                        *:ReviewClose*
Buffer-local :ReviewClose wq / q / x exposes normal local composer completion
for scripts. No close/unload/window/editor action initiates provider writes.

                                                        *buf-review-navigation*
:Review next [todo|comment|file]
:Review previous [todo|comment|file]
    Navigate stable backend order with wraparound. Todo is default;
    todo/comment skip Done; file skips viewed. Native ]c/[c handle hunks.
    Internal pane changes preserve jump history. Ordinary user motions still
    record jumps normally.
PR state fetches run git fetch --all first. Pull updates remote evidence;
the comparison follows checked-out HEAD. Fetch does not pull or switch branches.
:Review context
    Open selected comment's recorded original code in separate reusable context
    tab. Available exact revisions show diff/file; otherwise recorded hunk and
    discussion stay readable. Never invent missing revisions/locations.
:Review relocate [draft-id]
    Select desired line/range in current diff, choose unpublished root, then
    inspect old/proposed anchors in composer. :w saves under same draft identity;
    :q! discards unsaved relocation. Published comments cannot move.
:Review resolve local|remote|edit
    In selected conflict: retain local intent, discard conflicting local intent,
    or edit resulting body. Changes remain local until publication. Deletion
    conflicts cannot use edit. Deleted remote targets cannot be resurrected by
    local/edit; remote abandons stale intent. Retained text stays readable.
:Review log
    Read the session's complete append-only event/result timeline, newest first.
    Each folded row shows its generation and action summary. Enter expands
    readable details; Recorded payload is a nested fold containing the complete
    original JSON. Native zo/zc also work. Errors are highlighted. No timestamps
    are inferred, and viewing history never changes saved work.

Refresh preserves saved intent; conflicting remote changes appear
in a Local / Remote / Previously observed discussion view. A conflicted
publication blocks later writes until resolved.

Comment navigation shows up to three panes: original base, commented version,
checked-out HEAD. The original anchor is used even when GitHub has relocated
it. Head-side comments use their original head version; base-side comments retain
their original base version. Replies use the root's anchor.
Empty adjacent file diffs contract their panes, retaining the commented buffer
and its exact anchor. Both diffs empty leaves one pane; equal nonadjacent versions
still keep three panes when both adjacent diffs contain changes.
The commented version shows additions versus its original base in green and lines
removed toward checked-out HEAD in red. Red takes precedence on overlap.
Winbars identify versions, commits and paths. Renames are followed; absent files
remain distinct from empty files. Unknown original base-side context is labelled
Reconstructed; only verified original lines are jumped to or highlighted. Missing
history shows the recorded hunk above the thread. File navigation restores the
ordinary base/HEAD diff, with a dirty local file editable on the right. A comment
on HEAD normally contracts to original base and commented version. Replies/Done remain available in historical
threads; new roots and file-viewed marks require current code. PR-wide comments
retain code.
:Review context still opens original code explicitly in its auxiliary tab.

Long-running publication, PR fetching and Git preparation show one updating
command-line progress message. Counts are per phase and include confirmed work
on publication retries. Publication remains active through its final refresh.
Background and stale requests do not replace foreground progress.

CLI callers receive newline-delimited JSON progress on stderr, alongside ordinary
error diagnostics. Records have event="progress", stage, message, and optional
completed/total counts. Stdout retains the final response. Progress is ephemeral;
it adds no SQLite state and cannot change publication results.

Git supplies file contents directly; SQLite retains snapshots, anchors and
receipts. Confirmed receipts preserve your exact original comparisons across
imports/sessions. PR preparation refetches locally pruned objects when possible.
SQLite shares fetched payloads; workspace history stores references and field
changes. Unchanged fetches reuse matching snapshots. Only the current database
format is supported; incompatible databases are rejected without conversion.
Reader buffers have stable numbered names and are reused during navigation.
Manual splits keep their original target, including in other tabs; another slot
is used when needed. Composers keep private buffers and reserve their return
readers until close. Outgoing panes leave diff mode before reuse; hidden slots
do not remain registered in native diffs. Ordinary user diff buffers stay intact.
